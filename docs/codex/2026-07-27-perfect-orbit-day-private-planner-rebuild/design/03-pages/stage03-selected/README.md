## Page-family consequences

- **Today:** compact Pulse plus one continuous Stream; no Orbit, duplicate next card,
  giant greeting or capture backing strip.
- **Tasks:** planar searchable work list; desktop list/detail continuity; creation is
  separate from normal view-first row navigation.
- **Plan:** day/week/month and unscheduled tray with realistic capacity; wide Windows
  may use list/plan/detail panes.
- **Habits:** rapid method-specific logging in rows; full streak, recovery and history
  live in detail rather than bloating every list item.
- **Detail:** route on phone, contextual pane where width permits; explicit Edit;
  calendar/history/analytics/lifecycle remain reachable.
- **Capture/AI/Voice:** one anchored morphing surface with independent drafts; opening
  does not request IME; AI writes remain proposals until review/apply.
- **Secondary workspaces:** Goals, Projects/Areas, Notes, Focus, Reviews, Categories,
  Settings/Diagnostics and Feedback remain organized under More until a larger
  composition can promote them without changing route identity.
- **Native widget:** same status/log semantics, scrollability and local-first queue;
  Stage 48 receives a dedicated native preview family rather than a shrunk app page.

## Stage 04/05 acceptance

Stage 04 must create every foundation and component artifact named by the registry,
including anatomy, state, responsive, accessibility, motion and neighbor plates.
Stage 05 must then compose those accepted components into phone portrait/landscape,
tablet portrait/landscape and continuously resizable Windows page families with
empty, sparse, dense, light, dark, offline/retry/error/conflict, mixed-direction,
200% text, reduced-motion and IME evidence.

No shipped Flutter/native visual rebuild is authorized by this README alone.
